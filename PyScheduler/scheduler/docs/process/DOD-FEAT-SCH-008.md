## 2. Чек-лист готовности атомарного PR

Расширение минимального DoD из SPEC §2; при противоречии приоритет у SPEC.

### 2.1 Объём и зона ответственности

- [ ] Одно содержательное изменение (R3): не более одного алгоритма **или** одного контракта на PR.
- [ ] Файлы — строго в зоне ответственности: `PyScheduler/SCHEDULER.py`, `PyScheduler/tests/baseline/`, с шага M8b — каталог нового модуля планировщиков. Правки чужих модулей, файлов корня репозитория и общерепозиторных настроек «заодно» недопустимы; в ревью PR #37 именно «куча нецелевых изменений и переходов в другие блоки из своей зоны ответственности» стала первой причиной отклонения.
- [ ] Каждое изменение существующего теста имеет явную причину; «подбивание тестов под сделанный функционал» недопустимо (замечание ревью PR #37).
- [ ] PR обозримого размера: «в следующий раз не будем такие большие MR делать» (ревью PR #20); «до целевых изменений не добрался, столько времени на кодревью ни у кого нет» (ревью PR #37).

### 2.2 Код

## 3. Gate шага (SPEC §8.1) — операционный чек-лист

Для каждого шага M1–M8e до слияния и до старта следующего шага:

- [ ] чек-лист раздела 2 выполнен полностью;
- [ ] зелёные тесты → merge → регенерация снимков на новой `dev` (RUNBOOK §6) → `meta.dev_revision` равен SHA слияния;
- [ ] способ отката известен и проверен мысленно на шаге (R5): revert PR или legacy-маршрут фабрики;
- [ ] следующий шаг не начинается, пока текущий не слит (8.1);
- [ ] «полуготовая архитектура, которая заработает после последнего шага» не поставляется (R4): каждый слитый PR оставляет `dev` рабочей — все восемь алгоритмов доступны по прежним именам (R1).
